# 主播复盘入表台

> 篝火出品 · 收录于篝火 App 应用区

上传抖音、视频号、快手直播复盘截图，识别关键指标一键写进飞书多维表格

到 [Releases](https://github.com/campfire-code/live-review-to-feishu/releases/latest) 下载对应安装包：

## 怎么用

把一场直播在抖音、视频号、快手三个后台的复盘截图，识别成数字，写进飞书多维表格的**同一行**，之后还能在工具里查、改、删。

**准备（只做一次）**
1. 左侧「设置」：填写支持**看图**的多模态大模型的接口地址、密钥、模型名（兼容 OpenAI 接口格式）。密钥只保存在本机。
2. 顶部「飞书设置」：到飞书开放平台创建「企业自建应用」，开通多维表格权限（文档写明 `bitable:app` 或 `base:app:create` 之一即可建表），发布应用后，把 App ID 和 App Secret 填进来，点「测试连接」。
3. 多维表格有两种方式：直接去「录入」写入一条，工具会自动新建表格并建好字段；或在飞书里自己新建多维表格，把这个应用添加为协作者（可编辑），把地址栏链接粘贴到「使用已有的多维表格」，点「检查并补全字段」。**未核实**：应用新建的表格你本人的账号默认是否有权限打开，建议用第二种。

**每场复盘**
1. 「录入」页新增并选择主播，确认复盘日期，加群数、备注可选。
2. 三个平台各放一张截图（点框选择，或把图片拖进窗口，文件名含「抖音 / 视频号 / 快手」会自动放到对应位置）。快手截历史列表，只取第一行。
3. 点「识别截图」。识别出的指标显示在每张截图下面，**每一项都可以改**，带 * 的是核心指标。也可以点「手动填写」不识别。
4. 工具会自动**抽检**：核心指标缺失、读不成数字、百分比超 100%、必然成立的关系被打破（如进房人数大于曝光人数、在线峰值大于观众数、开关播时间与时长对不上）都会列出来。「需处理」类问题需要你改正，或勾选「我已核对，仍然写入」；「核对」类只是提醒。
5. 点「写入飞书」。首次写入会自动建表、建字段。
6. 「记录」页可搜索、同步、编辑、删除。第二天补录加微：点某行的编辑，填各微信号加粉数，自动算加微总数、加微率和私域分配（微信号清单在「飞书设置」维护）。

**其他说明**
- 截图只发给你自己配置的大模型接口，不经过其他服务器。
- 「写入」「编辑」「删除」操作的都是你自己的飞书表格；删除前会二次确认，且无法在工具里恢复。
- 没有内置本地 OCR：看图识别需要多模态大模型；没配置时仍可手动填写后写入。
- 日期按北京时间存入飞书日期字段；各平台指标以文本原样存入（如「1,914」「14.5%」），便于核对原始截图。
- 一次最多读取 5000 条记录。

## 验收用例

`samples/` 里是三张**虚构**的示例截图（示例主播·小满，图上标明「示例截图 · 虚构数据 · 非真实后台界面」）。以下用例需要自己的大模型和飞书自建应用（接口层已用假数据做过自动测试，真实联调见下表末尾说明）。

| 操作 | 应得到 |
|---|---|
| 「飞书设置」填错的 Secret，点「测试连接」 | 红色提示失败，并显示飞书返回的原因；填对后提示「连接成功」 |
| 「录入」新增主播「示例主播·小满」，日期 2026-10-26，把 3 张示例截图一起拖进窗口 | 三张图自动放进抖音、视频号、快手三个框 |
| 点「识别截图」 | 三个框都显示「已识别 n/n」；抖音「收获音浪」18,640、「曝光人数」48,210、「进房人数」2,048；视频号「观看人数」3,150；快手「直播观众数」1,806、「直播时长(分钟)」148。下方「抽检通过」（模型偶有误读，以截图为准，可在框里直接改） |
| 把抖音「曝光人数」改成 `48,21O`（字母 O） | 该格标红，抽检出现「需处理：读不成数字」，「写入飞书」按钮变灰，勾选「我已核对，仍然写入」后才可点 |
| 把抖音「进房率」改成 14.5% | 该格标黄，抽检出现「核对：与进房人数/曝光人数算出的 4.2% 差距较大」，不影响写入 |
| 点「写入飞书」（首次，未连接表格） | 日志出现「已新建多维表格…」「已写入」；飞书里新表有「主播、日期、识别方式、备注、加群数、加微总数、加微率、私域分配」和三平台共 38 个指标列，本场一行填齐 |
| 「记录」页点同步 | 看到刚写入的一行，日期 2026-10-26 |
| 点该行编辑，加群数 80，添加两个微信号加粉 25 和 18，保存 | 飞书里该行「加微总数」43、「加微率」53.8%、「私域分配」`号名:25 / 号名:18`，其他列不变 |
| 点该行删除 → 确认删除 | 行消失，飞书里同步删除 |

自动测试用手写的飞书接口响应和假大模型覆盖了以上流程（`pnpm test`）；真实飞书应用与真实大模型的联调列入待联调清单。

## 核实记录

以下接口地址、方法、字段类型已对照飞书开放平台文档（2026-10-27 读取）核实：
- 取令牌：`POST /open-apis/auth/v3/tenant_access_token/internal`，请求体 `app_id`、`app_secret`，返回 `tenant_access_token` 与 `expire`（该页注明为旧版接口，仍可用，新版接口见官方文档）。
- 新建多维表格：`POST /open-apis/bitable/v1/apps`，返回 `app.app_token`、`app.default_table_id`、`app.url`；权限 `base:app:create` 或 `bitable:app`。
- 字段：`GET/POST /apps/:app_token/tables/:table_id/fields`、`PUT/DELETE .../fields/:field_id`；类型 1 文本、2 数字、5 日期；字段名重复错误码 1254014；索引列不能删除（1254046）；列字段每页最多 100（参考实现写的 500 是错的，本工具已改）。
- 记录：`POST/GET .../records`、`PUT/DELETE .../records/:record_id`；日期字段写毫秒时间戳，文本写字符串，数字写数字；列记录每页最多 500，按 `page_token` 翻页；新增记录的错误码 1254045 表示字段名不存在。官方提示列记录接口为旧版，推荐「查询记录」接口，本工具仍用列记录接口（未改用新接口）。

**未核实**：新建多维表格时默认带的示例列名称（取自参考实现）；多维表格链接格式 `/base/<app_token>?table=<table_id>`；应用身份新建的表格对用户账号的默认可见性；各错误码对应的中文提示里除上面写明的以外均为通用表述。

## 自己编译

需要 Node.js 22、pnpm、Rust。

```bash
pnpm install
pnpm test          # 单元测试
pnpm tauri dev     # 开发运行
pnpm tauri build   # 打包
```

界面框架在 `src/kit`（所有 campfire-code 工具共用），本工具的逻辑在 `src/tool`。
